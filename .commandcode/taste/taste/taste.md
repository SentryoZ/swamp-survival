# Taste
- Wants existing bugs fixed before adding new features — explicitly sequences work so known defects are resolved first rather than layered over with new mechanics. Confidence: 0.7
- Cares about long-term maintainability/architecture, not just working code — asks the agent to self-review the codebase before building more, framing it around wanting to add features later, so structure/scalability is a first-class concern; willing to pause feature work and spend a whole session on a pure no-behavior-change structural refactor ("do refactor") when it unblocks future work. Confidence: 0.65
- Writes short, terse prompts (often lowercase, minimal punctuation) and delegates the specifics/design decisions to the agent rather than spelling out requirements. Confidence: 0.65
- Verifies web work on real devices (e.g. opens the dev server from a phone over the LAN with `--host 0.0.0.0`) rather than trusting only headless/desktop testing. Confidence: 0.5
- Wants projects to be playable/usable on mobile with touch controls, not desktop-only — asks for mobile support, flags UI that is oversized for small screens (e.g. upgrade cards too big), and expects the design to work one-handed on a phone. Confidence: 0.6
- Works iteratively by asking open-ended follow-up questions and requesting the agent brainstorm/expand the design space ("think more...", "add more weapon type?", "do we have limit?", "how about fuse weapon?", "How about Meta-progression? what would u do") before committing to an implementation. Confidence: 0.6
- Delegates roadmap/prioritization judgment to the agent — regularly asks it to pick or recommend what to build next (e.g. "which feature we should add now?") rather than deciding the order himself. Confidence: 0.45
- Prefers UI that surfaces concrete before→after numbers/stat deltas rather than vague label-only descriptions. Confidence: 0.45
- Prefers self-contained, dependency-free test/demo tooling over integrated tests — asks for a single standalone HTML page (inline CSS+JS, no build, works via `file://`) to manually audition a subsystem in the browser. Confidence: 0.45
- Wants progression/economy costs to be steep and hard-earned rather than cheap — when shown upgrade costs, immediately asks for large multipliers (e.g. double all costs, ×10 on the most powerful upgrades) to stretch out the grind. Confidence: 0.4
- Prefers expanding content breadth over tweaking existing numbers — when offered a rebalance of current systems (e.g. pacing/cost tuning), declines and asks for more new options instead (more sub-weapons, more fusion recipes). Confidence: 0.5
- Favors interlocking/combinatorial mechanics with exclusivity and trade-offs — explicitly wants items to feed several different combination recipes while being consumable into only one result, so choices carry meaningful, mutually exclusive consequences. Confidence: 0.4
- Repeatedly probes how existing things actually work, both before deciding on changes and after a feature ships — asks for exact formulas, numbers, tables, edge cases (rarity odds, caps/limits, haste math, spawn rate, XP curve, upgrade cost tiers), and how a feature is implemented under the hood (e.g. how sound is synthesized with no asset files). Often wants these numbers laid out as compact comparison tables. Confidence: 0.65
